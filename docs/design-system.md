# ONEPASS design system — Intaglio

What the interface is made of, and why. Written for whoever builds the next
screen. The living reference is the playground at **`/design`** (open in
development; platform staff only in production) — every specimen there is the
product's own component, so if it looks wrong there, it looks wrong everywhere.

---

## The idea

The visual language is called **Intaglio**, after the printing process used for
passports, banknotes and rail tickets: fine engraved line-work, paper you can
feel, ink with depth, and a few surfaces that catch the light. It is the
language of documents people trust with their identity and their money — which
is what this product asks to be trusted with.

Three rules, and everything else follows from one of them:

1. **The room and the objects are different materials.** Pages are paper and
   ink. Passes, tickets, receipts, warranties and credentials are *printed
   stock* with their own colour that does not change with the theme — a boarding
   pass is the same card in a bright room and a dark one.
2. **Colour means something.** Jade is the brand and the action. Marigold is
   value: points, savings, a good fare. Vermilion is danger. Indigo is
   information. Nothing is coloured for decoration.
3. **Light and dark are designed separately.** Light is paper in daylight —
   warm, tactile. Dark is night ink — deep green-black, accents lit from within.
   Dark is not light inverted.

What it deliberately is not: purple AI gradients, endless glass cards, default
component-library look, stock photography standing in for places we have not
photographed, animated counters, charts with no data behind them.

## Type

Archivo — one variable family with **width** and weight axes — does display,
figures and the condensed labels printed on tickets. IBM Plex Sans is for
reading (it has a Devanagari cut, so Hindi arrives in the same voice). Plex Mono
is for references and code. All self-hosted.

| Role | Class / token | Setting |
|---|---|---|
| Hero | `.display.hero` | Archivo expanded 780, `--fs-hero` |
| H1 | `.display.h1`, `.page-head h1` | expanded/wide 760, `--fs-h1` |
| H2 | `.h2` | wide 720 |
| H3 | `.h3` | normal 650 |
| Body | default | Plex 15–16px / 1.6 |
| Lede | `.lede` | Plex, larger, muted |
| Label / eyebrow | `.eyebrow`, `.stat-label`, `.ticket-label` | Archivo condensed caps, tracked |
| Figures | `.figure`, `.figure-lg`, `.num`, `.stat-value` | Archivo wide, tabular lining |
| Money | `<Money minor={…} />` | rupees full size, symbol and paise smaller |
| Technical | `.mono`, `code` | Plex Mono |

Money is always integer minor units until `<Money>` or `formatMoney` renders it
(`en-IN`, `₹`). No floats in the frontend, ever.

## Colour

Use the semantic tokens, never a hex, outside `tokens.css` and the object
stock.

| Token | Meaning |
|---|---|
| `--ground` `--surface` `--raised` `--sunken` | the room: page, sheet, lifted sheet, well |
| `--ink` `--ink-2` `--muted` | text, from primary to quiet — all ≥ 4.5:1 on every ground |
| `--line` `--line-2` `--rule` | hairlines, stronger lines, deliberate rules |
| `--accent` (+ `-strong`, `-soft`, `-line`, `-ink`) | jade: the brand and the primary action |
| `--value` (+ `-fill`, `-soft`, `-ink`) | marigold: money saved, points, a good fare |
| `--ok` `--warn` `--bad` `--info` `--offline` (+ `-soft`) | state |
| `--stock-*` | printed-object colours; theme-independent |

Registers (`data-surface` on each shell) change temperature and density, not
the palette: `consumer` (warm, spacious, full ambience), `partner` (denser,
half ambience), `control` (densest, no ambience, a night-ink rail and indigo
accent in both themes), `developer` (quiet, monospace given weight), `public`.

Theme: `data-theme` on `<html>`, stamped on the server from the `op_theme`
cookie (so no flash); absent means follow the system. `<ThemeToggle>` lives in
Settings, the public footer and the playground. **Never define a colour only
inside a media query** — the explicit `[data-theme='dark']` block repeats the
dark values.

## Materials

| Material | Class | Use |
|---|---|---|
| Core surface | `.card`, `.surface` | the working sheet |
| Elevated | `.card-lift`, `.surface-lg` | something the page is about |
| Sunken | `.card-sunken`, `.card-flat` | secondary groups, wells |
| Glass (vellum) | `.glass`, the app bar, dock, palette | **only** what floats above content |
| Immersive | `.immersive` (+ `<Guilloche pattern="field">`) | a stage for a story: landing hero, travel header, verification verdict, auth scene |
| Object | `.pass`, `.ticket`, `.receipt`, `.certificate`, `.poster` | things a person carries |

Glass has fallbacks: no `backdrop-filter` support, `prefers-reduced-transparency`,
and the lite tier all get an opaque surface.

**Objects** use the security-print vocabulary — guilloche (a CSS mask over the
generated patterns, coloured by the object), microprint, a foil strip that
follows the pointer on capable desktops (`<ObjectLight>`), perforations and
notches. Every decorative layer is `aria-hidden` and carries nothing the text
does not also say.

- `<Pass seed={publicRef}>` — ID-1 proportions. `seed` is a *public*
  reference; it rotates the line-work so every pass is its own. Never seed
  from anything personal.
- `<Ticket kind="boarding|event|venue|city|credential" state="valid|used|void|expired|pending">`
  — cream stock in both themes; the band colour says the kind before a word is
  read. Compose `Ticket.Main`, `Ticket.Band`, `Ticket.Title`, `Ticket.Route`,
  `Ticket.Fields`, `Ticket.Stub`, `Ticket.Stamp`. The stub stacks under the
  face on a phone.
- `<Receipt>` — thermal paper, monospaced, a torn edge.
- `<Certificate>` + `Certificate.Seal` — warranties and credentials.
- `<Poster kind seed city>` — the drawn image for a venue we have no
  photograph of. We do not use stock photography for real places: it would
  imply a place looks like something it may not.

## Motion

| Token | Value | For |
|---|---|---|
| `--t-instant` | 90ms | press feedback |
| `--t-fast` | 160ms | hover, colour |
| `--t-base` | 240ms | small moves |
| `--t-slow` | 380ms | content arriving |
| `--t-object` | 520ms | an object travelling (a pass opening) |
| `--ease-out` / `--ease-in` / `--ease-soft` | | arrive / leave / neutral |
| `--ease-spring` | sampled spring | things with mass only — never text |

Classes: `.rise` (content arriving), `.land` (an object arriving), `.stagger`
(a list arriving), `.reveal` (scroll-driven, never hides content),
`.pulse-once` (draw the eye once). **Spatial continuity**: navigations through
`<TransitionLink>` run inside `document.startViewTransition`; elements with the
same `view-transition-name` on both pages travel between them (the nav bead,
the dock bead, the pass). Falls back to an ordinary link where unsupported.

Every effect has to answer: does this communicate state, hierarchy, navigation,
physicality or identity? If not, it is removed.

## Performance tiers

`<PerformanceTier>` sets `data-tier` on `<html>` once, from signals the browser
exposes (never the user agent):

- **full** — fine pointer, ≥1024px, ≥6 cores, ≥4 GB: pointer-lit objects,
  ambient drift.
- **standard** — the default and the no-JavaScript state: transforms and
  opacity only.
- **lite** — reduced motion, data saver, ≤2 cores or ≤2 GB: no blur, no grain,
  no foil, no continuous animation, no view transitions.

The product is complete and correct in all three.

`prefers-reduced-motion` collapses every duration globally and stops anything
continuous; functional feedback (focus, state change) stays.

## Shells

- **Consumer** (`app/(app)/layout.tsx`): app bar (brand, desktop nav with a
  bead, command palette, pass button on desktop, bell with a counted unread
  badge, avatar → profile); on a phone a floating dock of five — Home, Explore,
  **Pass** (a miniature card, centre), Travel, Wallet. Lists in
  `components/consumer/places.ts` (`dock`, `desk`); the palette offers every
  place.
- **Consoles** (`ConsoleShell`): rail of sections (filtered by permission —
  a courtesy; each page authorizes for itself), sticky bar, wide main; the rail
  becomes a `<details>` menu under 1024px.
- **Auth**: one column on a phone; on a desktop the other half is an immersive
  stage with a pass reading "Your name". No field or link on the stage.
- **Public**: `SiteHeader` / `SiteFooter`.

Every page inside a shell provides its own container (`.wrap`, `.wrap-wide`,
`.wrap-narrow`) and opens with `<PageHead>` (consumer, public) or the console
`PageHeader`.

## States

Every important screen handles: **loading** (`loading.tsx` → `LoadingState` /
`Skeleton`), **empty** (`Empty`: what it is, why it is empty, what to do),
**error** (`ErrorState` with the request id), **permission** (the 404
doctrine — an unauthorized resource does not exist), **unavailable** and
**NEEDS_CONFIG** (`StatusChip` / `FeatureNote` from `lib/features.ts` — never
an ad-hoc label), **processing** (never shown as success), **partial**,
**cancelled/expired** (unmistakable, the object greys and is stamped), and
**offline** (`OfflineState`; tickets opened once work offline).

Honesty: no screen claims a payment, booking, refund, discount, cashback or
reward the backend has not confirmed; no screen calls deterministic logic AI;
no fabricated inventory; NEEDS_CONFIG is shown as NEEDS_CONFIG.

## Accessibility

Semantic landmarks and one `h1` per page; visible focus (2px jade outline,
offset); 44px targets for primary controls, 24px minimum anywhere; no
hover-only action; status never by colour alone (stamps carry words); dialogs
are native `<dialog>` or labelled `role="dialog"` with focus return;
`aria-current` on navigation; `aria-live` for asynchronous results;
`scripts/a11y.mjs` re-measures contrast and targets in both themes.

**The 24px rule was written here before it was true.** Checkboxes and radios were
18px for as long as the sentence above claimed 24px, and nothing caught it because
the audit covered consumer screens and `/control` and no partner console page.
Adding the counter — a screen somebody uses standing up, one-handed, with a queue
— found it in one run. The base rule now sets them to 24px globally, and the
partner console is in the audit list. A stated rule that nothing measures is a
preference.

**`hidden` needs a rule of its own.** The UA stylesheet's `[hidden]` is the
weakest thing in the cascade, so any layout class — `.grid`, `.row`, `.stack` —
silently wins and the element stays on screen while the markup says it is gone.
`base.css` settles it with `[hidden] { display: none !important }`, one of the
few places `!important` earns its keep. Found on the counter, where a fieldset
switched from `disabled` to `hidden` and stayed visible.

**`disabled` is not read-only.** A disabled fieldset is left out of the form
submission entirely, so using it to lock a section during a review step posts an
empty form. Hide the fields and send the reviewed figure back for the server to
check against, or make the controls `readOnly` individually.

## Rules that are not negotiable

- No hardcoded brand name in JSX — read `BRAND` from `lib/brand.ts`.
- No new colours outside `tokens.css`; no raster backgrounds; no stock photos of
  real places; no new icon libraries (`<Glyph>`).
- No client component for what the server can render — each `'use client'`
  names the browser API that forced it.
- No frontend filter as security; no V2 duplicates of a primitive.
- Money is integer minor units until `<Money>`.

## Renaming the product

`lib/brand.ts` holds everything a person reads as the name: `name`,
`shortName`, the wordmark split, `tagline`, `description`, console names,
microprint, the fallback person name, theme colours for browser chrome. The
manifest (`app/manifest.ts`), metadata, page titles (`titleTemplate`), the
wordmark, microprint on objects, aria-labels, notification and email copy all
read it.

**Not renamed with it** — technical identifiers other systems depend on: the
`onepass_session` and `op_theme` cookies, the `@onepass/pass` package, database
and role names (`onepass_consumer` …), the `x-onepass-signature` /
`x-onepass-timestamp` headers and the `ONEPASS-Webhooks/1` user agent partners
filter on, `op-*` CSS classes, storage keys, event type names. Renaming those
is a migration with a compatibility plan, not a find-and-replace.

A rename also needs: new wordmark split, the icon files in `public/icons` and
`app/icon.svg` if the mark changes, the service worker's offline copy
(`public/sw.js`), the docs, and the browser specs that assert on the name.
Stored rows written with the old name (existing notifications, seeded org
names) keep it until a data update.
